# 运维说明

部署与启动命令以 [云端说明](../cloud/README.md) 和 [Mac 说明](../mac/README.md) 为准。本页说明运行时需要关注的状态和恢复原则。

## 配置和凭据

公开配置模板位于 `config/workbench.example.json`。将主机、路径、上游命令等本机配置写入被忽略的 `config/local.json`；生成的密钥、令牌与运行文件放入被忽略的 `runtime/`。

云端管理账户、Mac 各上游认证、agent 的 MCPHub 访问令牌、反向 SSH 密钥应分别管理。只把任务所需的服务授权给对应 agent。变更配置前备份；更新 MCPHub 持久化设置时，应避免运行中的缓存写回覆盖修改。

MCPHub 管理界面绑定云端回环地址，通过 SSH 本地转发访问。没有完成 HTTPS 与独立公网认证设计前，不应直接改成公网监听。

## 构建与清理

| 对象或条件 | 基线策略 |
|---|---|
| 构建数据文件系统 | 80 GiB ext4 loop，达到容量上限无法继续写入 |
| 系统盘可用空间 | 低于 20 GiB 拒绝接单并触发空间保护 |
| 构建数据盘可用空间 | 低于 2 GiB 拒绝接单并触发空间保护 |
| 单个构建任务 | 2 CPU、8 GiB 内存、30 分钟超时 |
| 清理调度 | 每 15 分钟检查 |
| 成功任务工作区 | 构建结束后删除源码与中间文件 |
| 失败任务工作区 | 保留 24 小时用于排查 |
| APK 与日志等输出 | 保留 7 天 |
| 依赖缓存 | 按 14 天与 20 GiB 策略回收，仅空闲时清理 |
| 下载保护 | 10 分钟锁，避免下载中的产物被回收 |

自动清理和 MCP 手动工具共同管理存储。运维流程为：先查看存储占用，再预览清理计划，最后执行过期清理或删除指定任务。不要手工递归删除运行中的任务目录，也不要对整台主机运行无范围限制的 Docker 清理。

构建数据配额不包含全部容器镜像和控制元数据。升级时仍需检查旧镜像、服务日志及 loop 文件所在系统盘的剩余空间。更改配额或移动 loop 文件系统前先停任务并备份。

## 例行检查

- 检查 MCPHub、编译 MCP 和清理调度是否运行，服务日志是否持续增长。
- 检查存储统计和清理结果，确认没有异常遗留的活动任务或长期下载锁。
- 通过独立令牌检查可见服务范围，确认未经认证的连接被拒绝。
- Mac 端检查认证代理和反向 SSH 重连状态；只做工具发现或状态查询即可，不必唤醒所有应用。
- 定期验证备份可恢复。备份配置和必要任务记录，避免不加区分地永久保存所有缓存和 APK。

## 常见恢复

**Mac 工具不可达：** 先确认 Mac 在线，再检查本地代理、SSH 隧道、云端监听地址与 Docker 网桥防火墙。不要用开放公网端口来绕过隧道故障。

**ComfyUI 报 Host 校验错误：** 检查代理是否连接原本的回环地址。保留原服务 Host 保护，由代理提供云端入口。

**构建因空间不足终止：** 查看各存储类别占用，预览和执行过期清理；仍不足时调整保留策略或增加容量。不要反复提交同一任务消耗剩余空间。

**云端服务重启：** 确认数据盘已挂载后再启动构建服务，检查旧任务状态是否被恢复或标记为中断。原部署已验证重启后任务记录和产物留存，新部署仍需自行验证。

**模拟器不可用：** 先用原本地 MCP 的只读状态工具排查。云端编译成功不意味着模拟器已经启动、安装 APK 或完成应用测试。

## 升级

固定并记录镜像、Python 包、JDK、SDK、AGP 以及 ARM64 工具版本。先用指定测试提交验证升级，再切换真实项目。更新上游 MCP 后，重新检查工具数量、名称与访问范围；接口数量变化不应被自动当作成功。
