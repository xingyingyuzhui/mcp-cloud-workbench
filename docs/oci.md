# OCI 主机与长期认证

这套架构可部署在已有 Linux 主机上，OCI 并非 MCPHub 的强制依赖。原部署选择 Ubuntu ARM64 的 Ampere A1（4 OCPU、24 GB 内存、200 GB 启动卷），把运行应用与模拟器留在 Mac，只把网关和编译放在云端。

账户注册、付款方式、实例额度及账单由账户所有者管理。不要把“资源配额”“构建盘硬容量限制”和“费用硬上限”混为一谈。本仓库没有实现 OCI 账单封顶或自动停机策略，200 GB 启动卷中的80 GiB循环盘也不是新购买的块存储卷。

## 认证分工

- OCI 管理 MCP：使用 [Oracle 官方 MCP 项目](https://github.com/oracle/mcp) 的 OCI Cloud Server，按上游文档安装和配置。
- 临时控制台/会话认证适合首次操作；长期管理可采用 OCI API signing key profile。私钥留在本机，只有公钥上传到账户。
- 操作系统管理使用 SSH key。
- Mac 反向隧道使用另一个专用、无 shell 的 SSH 账户及 key。
- MCPHub 访问密钥再按服务或分组授权，不与 OCI API key 混用。

这些 key 不是“永不过期且无需维护”的凭据：可撤销、应轮换，权限随用途分开。不要把实际 OCI config、OCID、私钥、公钥绑定记录、会话 token 或主机 IP 放进公开配置。

本仓库不复制原会话的开户、提权、API key 注册与实例创建脚本，避免把一次性账户变更变成默认部署动作。机器准备好以后，从[云端部署说明](../cloud/README.md)开始。原服务无需重新部署就能把本仓库作为代码和文档的维护入口。
